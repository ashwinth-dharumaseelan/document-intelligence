1What Records does

Legal and Operations hold records as scans, PDFs, photos and paper. Finding a clause means opening files one by one, key details are retyped by hand, and expiring documents are missed. Records turns every document into searchable, validated data:

  • Reads any document (PDF, scan, phone photo, Word, PowerPoint, English and Arabic) with AI.
  • Understands it: works out the document type and extracts the fields that type needs.
  • Checks it with business rules: totals add up, dates make sense, nothing expired or duplicated.
  • Makes it findable: search by meaning or exact words, an assistant that answers with sources, a library, KPIs.
  • Acts on it: a key-dates view and a weekly email for anything overdue or due within 90 days.

2How it was built, step by step

  1. Connected to Databricks. Confirmed the Databricks CLI and the DEFAULT login, then explored the workspace: the document_intelligence catalog, the sample volume, an answer key (truth.json) and test notes.
  2. Built the first pipeline (PDFs only). A medallion pipeline (bronze → silver → gold) for the 33 sample PDFs: parse, clean, classify, extract, validate. Added a vector search index for search by meaning.
  3. Extended to every file type. Images, Office and text files are routed automatically. Introduced the document-type registry: each type's fields and rules live in configuration, so new types need no code.
  4. Measured accuracy. Compared every extracted field with the answer key. Found and fixed real errors (a stripped letterhead, a missed licence manager, a print timestamp read as a date, an invented due date).
  5. Built the app. A Databricks App with Search, Library, Document details, Assistant (chatbot) and Insights, running with each person's own permissions. Added a Genie space for questions over the data.
  6. Opened it to all users. Granted read access to the business tables and search, and read/upload on the documents folder. Moved the answer key to a private volume.
  7. Added key dates and alerts. A live view of expiries, renewal-notice deadlines, hearings and deadlines, a Key dates page, and a Monday email.
  8. Automated processing. A job that runs the pipeline and refreshes search whenever a file arrives. Prepared email intake and wrote the IT steps for email and Teams.
  9. Added a new type from a real upload. An employee asset undertaking form arrived; added the asset_undertaking type with HR-specific fields and checks.
  10. Prepared the presentation. A picture-first demo page, platform-neutral, mapped to every item on the use case slide.

5The document-type registry

The registry tells the AI what each document type is, what to extract and how to check it. It is a JSON file, doc_intelligence_pipeline/config/extraction_schemas.json, loaded into config.extraction_schemas by scripts/load_schema_registry.py. There are 12 types today: invoice, receipt, business card, ID document, contract, legal notice, court judgment, power of attorney, trade licence, letter, asset undertaking and other.

EntryPurpose
descriptionHow the AI recognises the type (used by classification)
fieldsWhat to extract, with types (text, number, date, list, line items)
instructionsExtra guidance, e.g. "never calculate a due date from payment terms"
validation_rulesBusiness checks written as SQL, e.g. subtotal + tax = total
gold_tableThe business table the type lands in
ground_truthHow the type's fields map to the answer key, for accuracy scoring

Core fields are extracted from every document: number, date, issuer, recipient, parties, currency, total amount and language. Each type has a schema_version, bumped on every change, and each record keeps the version that produced it.

6The pipeline

doc_intelligence_medallion is a Lakeflow Declarative Pipeline on serverless compute. Code: doc_intelligence_pipeline/src/transformations/, files 01 to 13 in run order. Streaming tables (bronze, silver) process each file once, which keeps AI cost flat. Materialized views (gold) are recomputed on every run, so rules and KPIs stay consistent.

Bronze: receive

bronze.raw_documents: Auto Loader picks up new files in the volume and its sub-folders. Each file is stored with its metadata and a content fingerprint, then routed: ai_parse (PDF, images, Word, PowerPoint), text (txt, csv, html, eml), excluded (answer key, test files) or unsupported. Files starting with _ or . are treated as hidden.

Silver: read, understand, prepare

TableWhat happensAI function
parsed_documentsOCR and layout: text, tables, headings, in English and Arabic. Cleansing: tables to rows, markup stripped, page numbers removed, whitespace tidied.ai_parse_document
documents_classifiedPicks one of the registry's types; writes a 60-word summary.ai_classify, ai_summarize
documents_extractedOne extraction step per type, generated from the registry. Cleansing: ISO dates, numeric amounts, trimmed text.ai_extract
document_chunksSplits documents into search passages with title, section and page context, plus document metadata for filtering.ai_prep_search

7Validation and accuracy

Quality is checked three ways:

  • Data-quality expectations on every layer: parse succeeded, text present, type known, extraction succeeded. Visible in the pipeline's data-quality view.
  • Business rules per type: e.g. invoice totals reconcile and the TRN is valid; an ID is not expired; a contract ends after it starts; an asset form is signed after receipt, approved after signature, and its serial number is not issued twice. Any failure sets the document to Needs review and keeps it out of the library.
  • Accuracy against an answer key: 73 known fields across 11 test documents. Currently 94.5% exact (69 of 73) and 100% counting partial matches, where the value is correct but includes extra detail.

The rules have already caught real problems: a received date read from a browser print timestamp was stopped by the "signed after receipt" check before it reached staff.

8Search, Genie and alerts

Vector search index

silver.document_chunks_index on endpoint doc-intelligence-vs. Each passage is converted to a vector by the databricks-gte-large-en model. A question is converted the same way and the closest passages are returned. Hybrid mode also matches exact words, for invoice numbers, case numbers and serial numbers.

Genie space: Records Document Intelligence

Turns plain-English questions into SQL over 17 gold tables, using business instructions ("for anything due or overdue, use key_dates") and tested example queries. It shows the SQL it ran so answers can be checked. Config: doc_intelligence_pipeline/genie/build_genie_space.py.

Weekly alert

SQL alert "Records: key dates due within 90 days" runs every Monday at 08:00 Dubai time. If anything is overdue or due within 90 days, it emails the list. Definition: doc_intelligence_pipeline/alerts/key_dates_alert.json.

9Automatic processing (the job)

doc_intelligence_auto_process, defined in resources/auto_process.job.yml.

PartSetting
TriggerFile arrival on the documents volume, including sub-folders. Waits 60 s after the last change, fires at most once a minute.
Task 1process_new_documents: runs the pipeline; only new files go through the AI steps.
Task 2refresh_search_index: runs src/jobs/sync_search_index.py so new passages become searchable.
SafetyOne run at a time; later triggers queue.

Tested: a file dropped at 07:25 was picked up at 07:28 and searchable at 07:31. The project is deployed in production mode so the trigger stays live.

Deployment

From records-search/: databricks bundle deploy, then databricks bundle run app. Databricks security-scans the code, installs packages, builds and starts the app. Query types are generated in advance and committed (shared/appkit-types/analytics.d.ts), so the app's own identity needs no data access to build. The app is billed for every hour it runs.

11One document, start to finish

An employee's laptop handover form, uploaded through the app:

  1. Upload. Add document saves it to the volume.
  2. About a minute later. The job's trigger notices the file and starts a run.
  3. Bronze. The file is stored, fingerprinted and routed to ai_parse.
  4. Silver. AI reads the form, classifies it as an asset undertaking, and extracts the employee, asset make and model, serial number, received date, signatures and approver. It is split into search passages.
  5. Gold. It lands in gold.asset_undertakings; all six checks pass, so it is Passed and appears in the library.
  6. Search refresh. The job updates the index; within about six minutes of upload staff can find it, ask the Assistant who has which laptop, or see it in Genie answers.

12Security and access

  • Each person's own permissions. The app runs searches, queries, file access and Genie as the signed-in user. Unity Catalog decides what each person can see.
  • The app has no data access of its own. Its identity can only call the AI model.
  • All users today can open the app, read gold tables and search passages, and read and upload documents.
  • Private: the answer key and test notes sit in a private volume. The email-intake identity records-email-intake can only read and add files.

Personal documents such as ID cards are currently visible to every app user. Before loading real HR records, restrict ID documents to the HR group and mask ID numbers for others (Unity Catalog row filters and column masks; the app follows them automatically).
